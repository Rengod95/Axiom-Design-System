# PRD01 · 제품 목적·대상 사용자·핵심 문제

상태: 전체 문서 기준선 검토안 · 목표 Foundation 1.0.0 · 2026-09-12

책임 역할: 제품 기획자. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## Axiom이 해결하려는 일

작은 제품 팀은 색상 표, Figma 컴포넌트, React UI 패키지, 모바일 구현, AI에게 주는 설명을 각각 유지한다. 토큰 하나를 바꿔도 어디까지 반영됐는지 확인해야 하고, 접근성·상태·의존성 규칙은 담당자의 기억에 남기 쉽다. Axiom은 이 정의를 사용자가 소유하는 하나의 명시적 시스템으로 만들고, 실제 프로젝트에 적용할 때까지 추적한다.

제품 약속은 “편하게 디자인 시스템을 정의하고, 그 정의를 지키는 플랫폼별 UI 라이브러리를 만든다”다. 코드 기반이라는 말은 사용자가 코드를 직접 써야 한다는 뜻이 아니다. GUI와 AI가 편집한 결과가 검증 가능한 문법·계약으로 남고 산출물의 코드·버전·출처를 사용자가 관리할 수 있다는 뜻이다.

## 첫 사용자와 성공의 차이

| 사용자 | 지금 겪는 비용 | Axiom에서 끝내야 할 일 |
|---|---|---|
| 1인 개발자 | 시스템 규칙을 만들 시간 부족 | 기본 DS를 수정하고 실제 앱에 설치 |
| 작은 제품 팀 | 여러 앱의 UI 버전·커스텀 차이 | 공통 버전을 고정하고 프로젝트별 업그레이드 |
| UX Engineer | 토큰·behavior·a11y를 수동 연결 | 재사용 계약과 검증 기준을 제작 |
| 코드에 익숙한 디자이너 | 시각 수정이 코드의 의미와 분리 | 내부 부위·상태·모션을 편집하고 구현 차이를 확인 |

모든 사용자가 처음부터 trait 문법을 알아야 한다면 제품 목표를 달성하지 못한다. 기본 템플릿, 쉬운 질문, 실제 preview, 필요한 순간의 설명을 제공한다. 전문가에게는 같은 결과를 세밀하게 조정하는 계약·타입·상태 보기를 제공한다.

## 핵심 가치와 경계

첫 번째 가치는 시스템 자체를 만드는 비용 감소다. DSF의 토큰·테마부터 컴포넌트의 부품·값·동작·접근성·모션까지 제작한다. 두 번째 가치는 그 시스템을 지키며 디자인하고 구현하는 비용 감소다. 검증 화면과 Agent가 같은 정의를 재사용하고, 출력은 실제 소비 프로젝트에 설치해 확인한다.

Axiom은 결제·가격·승인·고객 권한을 결정하지 않는다. Button은 활성화 요청을 보낼 뿐 주문 성공을 판단하지 않는다. Toast는 메시지를 표시하고 닫는 UI 수명을 관리하되 업무상 알림 시간을 강제하지 않는다. Brand Library는 로고·폰트·가이드를 따로 관리하고 실제 화면에서 DS와 결합한다.

## 성공을 판정하는 근거

디자인이 예뻐 보이는 것만으로는 충분하지 않다. 사용자가 도움 없이 기본 토큰을 바꾸고, Card를 만들고, Web/Mobile 차이를 편집하고, 오류를 이해해 수정하고, 실제 React·RN 프로젝트에서 쓸 수 있어야 한다. 정식 전체 지원에는 Swift·Android 및 전체 필수 카탈로그 검증도 포함한다.

조사할 지표는 첫 실제 설치 성공, 반복 시스템 수정 성공, DS 규칙 위반 발견·수정 시간, Agent의 계약 위반률, 프로젝트 업그레이드 성공이다. 현재 측정값은 없다. 화면 클릭 수나 생성 코드량을 최종 가치의 대리 지표로만 쓰지 않는다. 사업과 기술 선택은 이 사용자 작업을 얼마나 개선하는지로 평가한다.

## 결정 추적과 변경 영향
