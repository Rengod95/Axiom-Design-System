# SYN01 · ADS와 토큰 표준 선정 계약

상태: 전체 문서 기준선 검토안 · 목표 Foundation 1.0.0 · 2026-09-12

책임 역할: 문법/도메인 설계자. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## ADS가 필요한 이유와 토큰 규격 선택은 별개다

ADS는 토큰뿐 아니라 컴포넌트의 값·이벤트·행동·접근성·모션과 프로젝트 연결을 표현한다. 토큰 규격에 없는 컴포넌트 기능이 필요하다는 사실만으로 토큰 의미까지 새로 만드는 편이 낫다고 결론낼 수는 없다.

| 비교안 | 저장·해석 방식 | 예상 이점 | 확인할 비용 |
|---|---|---|---|
| A · 비교 기준 | DTCG 토큰 의미 + ADS의 상위 문서·컴포넌트 | 교환 생태계·의미 재사용 | 편집용 ID·그래프 연결 |
| B · 우선 실험 | ADS 내부 그래프 + DTCG 손실 관리 경계 | 동일 ID·revision·진단 모델 | 원본·확장·resolver 대응 |
| C · 조건부 후보 | 독립 토큰 의미와 교환 mapping | A/B로 불가능한 구체 이점 | 도구 생태계·migration·교육·검증 부채 |

A/B를 비교한 후 C가 동등 이상의 기능과 더 적은 전체 트레이드오프를 증명하는 경우만 채택한다. 증명하지 못하면 DTCG 전체 지원을 기준으로 한다. JSON 속성 이름이 더 짧다는 이유만으로 우수한 표준이라고 판정하지 않는다.

## 기능과 렌더링의 전체 지원

비교 기준 판본은 DTCG 2025.10의 [Format](https://www.designtokens.org/TR/2025.10/format/), [Resolver](https://www.designtokens.org/TR/2025.10/resolver/), [Color](https://www.designtokens.org/TR/2025.10/color/)다. 알려진 안정 판본을 고정해 의미·표현·오류 조건별 corpus를 만든다. 미래 확장까지 미리 지원했다고 표시하지 않는다.

지원표는 읽기, 원형 보존, 의미 해석, GUI 편집, preview, 타깃 출력, 실제 실행을 각각 가진다. 알려지지 않은 값의 JSON을 저장했다는 사실은 렌더링 지원이 아니다. 토큰이 shadow인지 transition인지에 맞는 대표 사용처를 정해 실제 결과를 시험한다. transition 토큰은 동작 프로그램 전체를 대신하지 않는다.

공간·단위·색역이 다른 타깃에서 의미 보존 변환이 필요하면 원값, 변환 규칙, 오차·대체 이유, preview 차이를 기록한다. 미지원 값을 조용히 빼고 전체 지원으로 계산하지 않는다. 플랫폼상 정확한 동일 표현이 불가능하면 승인된 대응 의미와 시험 기준을 정의하거나 해당 정식 지원을 보류한다.

## 비교 실험과 채택 문턱

동일한 corpus로 alias/순환/누락, 복합 값, metadata·확장 보존, resolver 조합, 모든 선언 색 공간·단위, 편집 후 교환, 네 타깃 표현을 대조한다. 성능뿐 아니라 추가 구현 코드, 장애 복구, 문서 난도, 개발·유지보수 시간을 기록한다. A안 대비 손실·임의 예외가 늘어나면 C안의 이점을 인정하지 않는다.

선정은 문법 책임자가 결과를 제시하고 제품 책임자가 확인한다. 현재는 선택 절차가 확정되었고 실제 우위는 미실증이다. 구현 착수 후 첫 문법 고정 전에 결론을 내린다. UI 편의만을 위해 저장 의미를 좁히지 않고 상세 편집·원본 보존의 경로를 제공한다. 전체 세부 필드 설계는 [계약 부록](../annexes/document-contracts.md)에 있다.

## 결정 추적과 변경 영향

<a id="d06-03"></a>

**D06-03 — 확정 방향:** 자체 토큰 표준을 조건부 허용한다. 동등 이상 기능과 더 적은 전체 트레이드오프가 입증되고, 선언한 표준의 전체 기능과 타깃별 렌더링을 지원해야 한다. 자체 표준의 이점이 확인되지 않으면 DTCG 전체 지원을 기준으로 한다. ADS의 컴포넌트 표현 필요성만으로 DTCG 토큰 의미를 대체할 이점이 입증되지는 않는다.
