# BRD01 · Brand Library와 사용 지침

상태: 전체 문서 기준선 검토안 · 목표 Foundation 1.0.0 · 2026-09-12

책임 역할: 브랜드 담당. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## 브랜드와 엔지니어링 시스템을 나누는 이유

로고 사용 여백과 Select의 키보드 동작은 모두 품질에 중요하지만 같은 종류의 규칙은 아니다. Brand Library는 로고·폰트·이미지·사용 지침을 제작·보관하고, DSF와 컴포넌트는 토큰·공개 값·UI 의무를 관리한다. 검증 화면이나 이후 Design Studio에서 두 가지를 함께 사용한다.

BrandLibrary는 독립 id/version을 가지며 프로젝트와 시스템이 특정 버전을 참조한다. 새 로고를 올려도 모든 소비 프로젝트에 즉시 적용하지 않는다. 라이브러리 업데이트를 확인한 뒤 사용자가 업그레이드한다.

## 관리 대상과 관계

| 대상 | 저장 정보 | 사용 관계 |
|---|---|---|
| 로고 세트 | 형태·밝은/어두운 배경용·최소 크기·여백 | assetRef와 guidelineRef |
| 폰트 | family·style·weight·언어 범위·파일·권리 | typography token과 연결 |
| 이미지·아이콘 | 원본·파생본·설명·장식 여부 후보 | 콘텐츠 slot·visual layer |
| 사용 지침 | 설명·좋은/나쁜 예·적용 범위 | 선택 가능한 측정 규칙 |
| 브랜드 변형 | 지역·제품군·캠페인 식별 | theme 축 또는 별도 library version |

브랜드 이름을 토큰의 불변 ID로 쓰지 않는다. 이름·표시 분류는 바뀔 수 있고 ID 참조가 안정성을 제공한다. 하나의 asset을 여러 시스템이 사용해도 저작권 정보는 내용 hash와 버전 관계로 유지한다.

## 지침을 검사하는 방식

기본은 설명과 예시다. 최소 로고 크기, 여백, 허용 asset처럼 수치·목록으로 표현 가능한 규칙만 선택 검사한다. “브랜드답다” 같은 판단을 자동 통과/실패로 위장하지 않는다. 자동 규칙에는 measurement, scope, threshold, severity, explanation, approvedException이 필요하다.

예를 들어 Card header에 로고를 넣고 여백을 줄이면 가이드 위반 표시와 수정 제안을 제공한다. 브랜드 정책의 예외를 승인했다고 텍스트 대비·조작 이름·포커스의 필수 접근성 검사가 면제되지는 않는다. 실제 접근성 충돌은 디자인 대안과 미준수 상태를 함께 보여 준다.

## 운영 흐름과 검증

외부에서 제작한 파일을 가져와 원본·출처·권리·표시용 변형을 등록하고 사용 지침을 붙인다. 시스템에서 선택해 사용하면 버전 고정과 실제 필요 자산 복사가 이어진다. 누락·권리 불명·폰트 대체는 관련 출력과 증거 상태에 전파한다.

라이브러리 변경 시 영향을 받는 token, component, screen, delivery release를 역추적한다. 로고 교체 후 dark theme에서 식별되는지, 폰트 교체 후 한글·영문 줄바꿈과 layout이 유지되는지 시험한다. 자산 byte 관리와 배포 조건은 [BRD02 · 자산 저장·출처·권리·배포](assets-and-provenance.md)가 소유한다.
