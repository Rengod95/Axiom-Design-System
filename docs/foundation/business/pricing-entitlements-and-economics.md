# BIZ02 · 무료·유료 경계와 운영 원가

상태: 전체 문서 기준선 검토안 · 목표 Foundation 1.0.0 · 2026-09-12

책임 역할: 사업/마케팅 담당. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## 무료의 가치와 비용을 분리한다

개인·작은 팀은 로컬에서 시스템을 만들고 내보내는 핵심 가치를 거의 무료로 경험하게 한다. 인원과 관계없이 Axiom 서버 저장·빌드·AI가 비용을 발생시키면 자원 과금을 검토한다. “1~2인이므로 무제한 서버 비용도 무료”로 해석하지 않는다.

다음은 가격표가 아니라 권리·과금 설계안이다. 정확한 금액·무료 사용량은 실측 뒤 결정한다.

| 사용 방식 | 비용 주체 | 과금 가설 |
|---|---|---|
| 로컬 편집·공개 코어 검사·소스 출력 | 주로 사용자 장비 | 개인 핵심 무료 |
| 공유 시스템 편집 | 서비스·협업 운영 | 3인 이상 편집 좌석 선호 |
| 읽기·다운로드한 코드 소비 | 서버 요청 여부만 별도 | 좌석 무료 |
| 호스팅 저장·빌드·장기 이력 | Axiom 인프라 | 팀 크기와 별도 자원 한도 |
| BYOK·로컬 AI | 사용자 공급자 | Axiom 모델 원가로 이중 청구하지 않음 |
| 향후 Axiom AI 서비스 | Axiom이 결제한 모델·실행 | 사용량·서비스 비용을 명확히 표시 |
| 기업 설치·감사·지원 | 도입·유지보수 인력 | 별도 계약 가설 |

동일인이 여러 프로젝트를 편집할 때 workspace 범위의 한 좌석으로 집계하는 안을 우선 검증한다. 서비스 계정·봇은 사람 좌석 대신 실행 자원·권한으로 관리하고, 사람 계정 공유로 좌석을 회피하는 정책은 이용 조건에서 다룬다.

## 참고 제품에서 얻는 구조

Builder는 Code와 Content, 좌석과 Agent 사용량을 구분한다. Axiom에도 제품 영역과 계산 원가의 구분은 유용하다. [Builder 가격 구조](https://www.builder.io/pricing)
UXPin과 Plasmic의 요금표는 팀 기능·기업 지원의 묶음을 비교할 자료다. 해당 가격을 Axiom 지불 의사의 증거로 사용하지 않는다. [UXPin](https://www.uxpin.com/pricing), [Plasmic](https://www.plasmic.app/pricing). 확인일은 2026-09-12이며 Axiom의 숫자는 아직 정하지 않았다.

## 측정할 단위와 결정 공식

월 직접원가 = 저장량×저장 단가 + 전송량×전송 단가 + 실행 시간×실행 단가 + AI 청구액 + 결제 수수료다. 여기에 지원 시간과 고정비를 별도 보여 준다. BYOK 비용은 사용자 총비용 분석에는 포함하지만 Axiom 매출·모델 매입액으로 잘못 집계하지 않는다.

작업별 meter는 workspaceId, resourceKind, quantity, unit, operationId, providerReceipt, occurredAt, dedupKey를 기록한다. 재시도·웹훅 중복은 같은 사용량을 이중 청구하지 않는다. 사용량 원장과 결제 상태는 디자인 문서 바깥의 서비스 데이터다.

## 요금 확정과 중단 기준

자가 사용과 비공개 사용자 시험에서 성공한 시스템당 비용, 반복 작업률, 유료 기능 요청, 지원 시간, 무료 사용자 유지 비용을 수집한다. 좌석 중심·자원 중심·혼합 안을 같은 고객 작업으로 비교한다. 실제 첫 유료 가치는 협업·호스팅·AI·기업 도입 중 수요가 확인된 묶음으로 선택한다.

한도를 넘으면 새 유료 작업 전에 예상 비용·중단·대체 로컬 경로를 알린다. 결제 실패는 사용자가 가진 파일을 삭제하는 이유가 아니다. 다운로드·복구 정책과 호스팅 유지 기간은 가격 공개 전에 명시한다. 예산이 거의 없는 초기에는 무제한 관리형 생성과 상시 native build 서버를 기본 제공하지 않는다.

## 결정 추적과 변경 영향

<a id="d39-01"></a>

**D39-01 — 확정 방향:** 개인 무료와 인원에 관계없는 호스팅 자원 과금을 선호한다. 정확한 무료 기능·라이선스·운영비 경계는 조사 후 결정한다.

<a id="d39-02"></a>

**D39-02 — 확정 방향:** 공유 시스템을 편집하는 사람만 과금, 읽기·코드 소비는 무료

<a id="d39-03"></a>

**D39-03 — 확정 방향:** 실제 사용자 수요를 확인한 뒤 첫 핵심 유료 묶음을 선택한다.

<a id="d39-07"></a>

**D39-07 — 확정 방향:** 가설·측정 방식·의사결정 시점을 먼저 정의하고 실측 뒤 사업 수치를 확정한다.
