# UX01 · 작업 공간·온보딩·Inspector·도움말

상태: 승인된 Foundation 1.0.0 설계 기준선 · 검토 2026-09-13

책임 역할: UX/UI 설계자. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## 첫 화면은 빈 문서가 아니다

처음 열면 기본 DS와 컴포넌트 템플릿이 import된 프로젝트를 제공한다. 사용자는 “직접 수정”, “AI와 시작”, “기본 원리 연습”을 선택할 수 있다. 시작 전에 모든 라이브러리·플랫폼·문법을 결정하도록 요구하지 않는다. 브라우저 보관과 로컬 폴더 보관은 동등하게 선택한다.

첫 연습은 대표 색 수정→Card body 바꾸기→Web/Mobile 비교→출력 준비 상태 확인이다. 단계를 건너뛰어도 기능을 잃지 않으며 도움말을 다시 열 수 있다. 기본 문서는 사용자 프로젝트에 복사되고 원본 템플릿 provenance가 남는다.

## 시작·빈 상태·실패에서 이어 가기

| 상태 | 화면의 다음 행동 | 보존할 정보 |
|---|---|---|
| 아직 프로젝트가 없음 | 기본 시스템으로 시작·기존 문서 열기 | 보관 방식 선택 전 기존 프로젝트를 만들거나 덮어쓰지 않음 |
| 템플릿 로딩·검사 실패 | 실패 이유·재시도·이미 준비된 템플릿 선택 | 입력한 이름·보관 선택; 미완료 import를 성공 프로젝트로 표시하지 않음 |
| 선택 대상 없음·검색 결과 없음 | 시스템 요약·새 토큰/컴포넌트 만들기·검색 조건 지우기 | 현재 문서·검색 조건; 이전 선택의 속성을 편집 가능한 것처럼 남기지 않음 |
| 폴더 권한 취소·저장 실패 | 재연결·다른 보관 위치·문서 내보내기 | 마지막 저장 revision과 저장 못 한 초안을 구별 |
| 첫 출력의 타깃·Host·검증 부족 | 부족한 요구에서 연결·검사·내부 시험용 출력으로 이동 | Card·토큰 편집과 마지막 검증본; 설치 성공으로 표시하지 않음 |

온보딩의 마지막 단계는 단순 export 버튼 클릭이 아니라 산출물 위치와 상태를 확인하는 것이다. 연결 가능한 소비 프로젝트에서는 init/doctor 결과와 실행 예제로 이어지고, 연결하지 않은 경우 소스 묶음과 설치 안내를 제공한다. 저장·출력의 실패 판정은 각각 [ARC04](../architecture/storage-offline-and-recovery.md)와 [DLV02](../delivery/project-init-and-doctor.md)를 따른다.

## 기본 화면 구조

좌측은 시스템·컴포넌트·레이어 탐색, 중앙은 직접 조작·preview, 우측은 현재 선택의 속성과 AI 대화다. 전체 시스템의 오류·미검증·저장 상태는 작업을 가리지 않는 상태 영역에 둔다. 패널 위치는 디자인 검토안이며 접근성·작은 화면 시험 후 세부 배치를 확정한다.

Inspector의 기본 순서는 내용·배치·외형·동작·접근성·모션이다. 선택한 대상에 관련된 항목만 먼저 노출하고 전문가 보기에서 trait, port, type, rule provenance를 펼친다. 기본값과 상속값, 사용자 override를 시각·텍스트로 구별한다.

## 자연스러운 의미 연결

사용자가 Card에 “클릭”을 추가할 때 목적을 선택하도록 제안한다. 독립 action, 링크 이동, 선택 중 어떤 UI 의미인지 구별하고 필요한 값·키보드·역할을 함께 설명한다. 단순히 사각형을 그렸다는 이유로 button으로 바꾸지 않는다.

“이름” 입력은 어느 조작부를 설명하는지 예제로 보여 준다. 새로운 slot의 내용 종류·개수는 자연어 질문으로 시작한다. 기술 ID는 필요한 경우 복사·검색할 수 있고 한국어 표시를 바꿔도 안정성을 유지한다.

## AI와 검토

선택 범위 AI 대화는 포함된 component·token·의무와 예상 변경을 보여 준다. 일반 로컬 외형 변경은 정한 정책 안에서 Undo와 함께 적용할 수 있다. 공유 토큰, 공개 API·행동·의존성·삭제·공유 영향은 검토 화면으로 연결한다.

검토 카드는 “바뀌는 것”, 영향 사용처·타깃, 진단, 적용/수정/거절을 제공한다. 승인되지 않은 patch는 실제 revision과 분리한다. 작업 도중 다른 패널에서 수정하면 충돌 부분만 비교하고 비충돌 작업의 선택 적용을 허용한다.

## 사용성 검사

한글·영어 첫 사용자가 용어를 외우지 않고 첫 토큰 수정과 Card 제작을 완료하는지 관찰한다. 키보드로 패널 전환·선택·수정·Undo·오류 복구가 가능해야 한다. 전체 속성 보기·즐겨찾기·패널 구성은 확장 보기로 관리하며 구체 초기 노출은 사용성 검증 결과로 정한다. 기능을 화면에서 숨기는 것과 지원 범위에서 제거하는 것은 다르다.

## 결정 추적과 변경 영향

<a id="d26-01"></a>

**D26-01 — 확정 방향:** 목적에 맞춘 온보딩에서 기본 DS·Card 수정과 AI 시작을 모두 제공하고 preview·출력으로 첫 성공 경험을 연결한다.

<a id="d26-02"></a>

**D26-02 — 확정 방향:** 디자인 중 관련 행동을 추가할 때 자연스럽게 제안

<a id="d26-03"></a>

**D26-03 — 확정 방향:** 기본 Inspector와 선택 범위 AI 대화를 함께 제공한다. 전체 속성 보기와 패널·즐겨찾기 구성은 확장 보기로 제공하되 출시 단계는 합의된 범위에서 정한다.

<a id="d36-03"></a>

**D36-03 — 확정 방향:** 작업 중 설명·예제·가이드를 기본으로, 인터랙티브 연습과 사용자 수준별 학습 경로를 선택 온보딩으로 조합한다. 원문의 '45번'을 4·5번으로 해석한 것은 정규화 기록에 남긴다.
