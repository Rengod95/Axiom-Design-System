# GOV01 · 문서 권위와 변경 승인

상태: 전체 문서 기준선 검토안 · 목표 Foundation 1.0.0 · 2026-09-12

책임 역할: 제품 책임자. 이 문서의 설계는 아직 제품 구현·실행 검증 완료를 뜻하지 않는다.

## 무엇을 기준으로 제품을 만드는가

Axiom에는 제품 책임자의 결정, 그 결정을 구현 가능하게 푼 설계, 실행 결과가 함께 쌓인다. “Button에 접근성 검사가 필요하다”는 요구와 “그 검사를 통과했다”는 사실은 서로 다르다. 문서가 길어져도 이 차이를 잃지 않는 것이 이 규칙의 목적이다.

권위 순서는 현재 사용자의 명시적 결정 → 해당 결정의 확정 기록 → 승인된 Foundation 규범 → 파생 설계·작업 계획 → 조사·과거 코드다. 새로운 대화가 기존 결정을 바꾸면 원문을 지우지 않고 대체 관계를 기록한다. 개발자가 조사 문서에서 더 편한 방법을 발견했다고 필수 타깃이나 사용자 소유권을 축소할 수 없다.

## 상태와 승인 단위

| 상태 | 뜻 | 허용되는 다음 행동 |
|---|---|---|
| ADOPTED_DIRECTION | 사용자가 목적·경계·선택 절차를 확정 | 상세 설계 작성 |
| DESIGN_REVIEW_READY | 상세 규칙·예시·실패 흐름을 작성 | 전체 기준선 검토·수정 |
| BASELINE_APPROVED | 특정 문서 묶음과 hash를 사용자가 확인 | 구현 부트스트랩 ADR 제안·구현 시작 |
| IMPLEMENTED | 해당 코드와 실행 경로가 존재 | 독립 검증 |
| VERIFIED | 특정 revision·타깃·환경에서 요구를 충족 | 증거 범위 안에서만 지원 표시 |

현재는 방향과 56개 문서 인덱스가 승인되었고 전체 본문은 검토 대상이다. “전체 문서화를 진행해줘”는 문서 작성 허가다. 결과를 보지 않은 상태의 전체 본문 승인이나 제품 출시 허가로 기록하지 않는다.

## 변경 요청의 최소 내용

ChangeProposal에는 id, 요청자, 이유, 기존 결정 ID, 변경 전후 규칙, 영향 문서·소비 프로젝트·검증 요구, 호환성, migration/rollback, 승인자와 승인 대상 hash가 필요하다. 오탈자·깨진 링크는 정정하고 기록한다. 공개 API, 저장 의미, 필수 품질, 권리·가격·지원 범위의 변화는 책임자가 승인한다.

예를 들어 Card 기본 유형에 “결제 성공” 상태를 추가하자는 제안은 UI 목적 경계를 바꾼다. 이를 조용히 새 enum으로 넣지 않는다. 앱이 표시할 내용을 전달하는 기존 값·slot으로 해결하거나 독립 제품 도메인 문서에서 다룬다.

## 충돌과 검증

한 규칙의 책임 문서는 하나다. 다른 문서는 왜 필요한지와 자기 영역에서 어떻게 쓰는지 설명하고 원문을 링크한다. 충돌 발견 시 더 최신의 확정 방향을 우선해 영향 문서를 함께 수정하고, 해석이 불명확한 부분만 결정 요청으로 남긴다. 확정 기록의 과거 시점 필드를 현재 상태처럼 덮어쓰지 않는다.

문서 검사는 56개 본문 존재, 129개 원 결정과 14개 보충 결정 추적, 로컬 링크·JSON·예시 참조, 도메인 경계의 모순을 확인한다. 실제 타깃 준수는 QAL 문서의 별도 증거가 필요하다. 이전 442개 파일의 Git 보존·복원 성공은 제품 기능 성공으로 이월하지 않는다.
