# Motion IR — implementation report

**Date:** 2026-09-02
**Status:** COMPLETE for N16
**Scope:** closed, backend-neutral Motion IR schema, cross-registry semantic
validation, and normative fixtures

## Outcome

N16 adds the serialized Motion IR authority without adding `defineMotion`, a
normalizer, generated/public TypeScript contracts, a runtime backend, or React
bindings. Those boundaries remain N18, N23, N31, and N33 respectively.

`spec/motion/motion-ir.schema.json` binds each artifact to the exact CSS profile
and Condition Registry digest. It models explicit Recipe and Slot identity,
ordered enter/exit/state-change phases, ordered segments, standard CSS property
tracks, tween/spring transitions, and mandatory reduced-motion policy.

## Reconciled decisions

- `MotionTrackIR.allowDiscrete` is required. It preserves the explicit opt-in
  for discrete CSS properties rather than allowing a backend to infer intent.
- Spring `bounce` is finite in `[0,1]`; `stiffness`, `damping`, and `mass` are
  finite and greater than zero.
- Two shorthand authoring values normalize to 0/1 offsets. Three or more
  keyframes require explicit finite, strictly ascending offsets with endpoints;
  mixed forms are forbidden.
- Every reduced-motion replacement segment carries its own transition. It never
  inherits a transition from the normal path.
- `recipeId` is explicit lexical identity only at N16. Recipe/Slot applicability
  awaits the Recipe contract.
- `pressed` is explicitly Motion-usable in the Canonical State Registry; the
  validator requires that usage marker for every `stateChange` target.
- `AXM1006` backend-transition support and `AXM1009` provider lifecycle
  capability are deferred to N31/N33.

## Semantic enforcement and evidence

The `motion-ir` semantic validator checks pinned profile identity, exact
Condition Registry digest, Motion-usable canonical State transition values,
CSS property motion policy, normalized keyframe endpoints/order, timing Token
Domains, and every keyframe's configured value kind/binding. CSS literals use
the public CSS-profile grammar validator; template Token segments are checked
against template bindings and synthesized as `var(--axiom-motion-token)` for
grammar validation. `motion: unknown` is retained as a warning for later
backend validation. Fixture suites now declare exact `allowedWarnings`; only
the Motion suite permits AXM1012, so unrelated warnings remain failures.

Ten positive fixtures cover Dialog popup enter/exit, backdrop tween, Button
pressed change, Token timing, direct and template Token keyframes, spring
configuration, ordered segments, and both reduced-motion strategies. Five
negatives cover unknown-property policy, non-empty invalid CSS grammar, illegal
Token binding, invalid IR transition kind, and a replacement segment missing
its own transition. The generated profile currently has no discrete or
not-animatable entry, so those branches remain injected-profile unit coverage.

The normative inventory is now **34 schemas**, **14 registries**, **24 fixture
suites**, **36 positive fixtures**, and **62 negative fixtures**. N17 is the
next implementation boundary.
