# Component editing delivery — 2026-09-15

This increment turns custom layouts into editable compositions and carries their source into generated React. It implements the owner's instance, policy, behavior, native verification and Library design request under [ADR-0019](../adr/0019-element-composition-policy-and-behavior-authoring.md). The earlier [authoring increment](studio-authoring-delivery.md) remains historical evidence for the composer, six token architectures and contextual token usage.

## Delivered behavior

- **Real instances:** insert a Library-created definition into a custom frame or content area. The instance stores source/design revision pins, scalar consumer overrides and exposed text content; it never duplicates the source definition. Interact changes transient consumer state only. Editing a source retains the instance's values and marks it stale until a reviewed update. Both Studio deletion and raw kernel deletion protect retained instances from newly missing sources. Imported missing sources remain recoverable. React emits real nested component functions and forwards descendant request notifications with the leaf instance identity.
- **Free elements:** add Box, Frame or Text without entering code identifiers. Element mappings, layout and reading order update together. Automatic flow and free positioning share the existing source model. Move/resize handles work at canvas zoom, keyboard arrows provide precise changes, and double-click text supports Ctrl/Command-Enter application and Escape cancellation. Edits use common review, Undo/Redo and reload. Empty boxes do not render their layer name as content.
- **Policies:** inventory minimums, primitive/semantic alias structure and compatible design-property bindings form three closed predicates. Rules can be advisory or required, project-wide or scoped to a component/category. Draft saving stays available; required findings block all target delivery. Locate opens the affected component, element and category. See [policy contracts](foundation-policy-authoring.md).
- **Behavior:** typed local state, press/change/focus/blur triggers, comparisons, ordered set/toggle actions and declared event emission. Consumer-owned values are read-only to local actions. Preview, simulator and generated React share the deterministic evaluator; redundant built-in semantic requests reject instead of firing twice. See [behavior contracts](component-behavior-authoring.md).
- **Library:** source-backed control geometry, token-bound filled/outlined variants and internal label hierarchy improve eleven representative semantic families, including button, text field, checkbox, switch, tabs and card. Provider references remain references; no upstream package is implied. See [design baselines](library-component-design-baselines.md).
- **Native verification:** the Native Runtime workflow compiles unchanged generated Compose/SwiftUI source and executes Android instrumentation/iOS mounted-render tests. Workflow creation, generation, compilation and runtime results are distinct. The current Windows host lacks the native toolchains; actual native results come from CI artifacts. Both platform jobs passed in [Native Runtime run 34929111813](https://github.com/Rengod95/Axiom-Design-System/actions/runs/34929111813) at `4f4b71e`, for the representative consumers and observed toolchains documented there. See [native verification](native-runtime-verification.md).

## Guardrails and remaining scope

Composition is limited to 64 instances per definition, eight nested levels and 1,024 expanded instances per root. Pins, owned identities, slot cardinality, content type, source profile, graph cycles and expansion budgets are checked before projection/delivery. Malformed imported composition produces diagnostics instead of throwing. Existing valid projects without these optional extensions retain their previous behavior and original source bytes.

Native targets explicitly reject custom composition, free HTML layout and authored behavior until mappings exist. This increment does not provide rich text/assets, constraints/rotation/vector tools, arbitrary scripts, a complete state-machine graph, inherited policies, approved policy exceptions, a remote component registry or full Figma/Foundation parity. It supports Library-created catalog definitions as reusable instances; legacy fixed starter definitions retain their separate profile.

## Verification and design

The [verification manifest](component-editing-verification.json) records final local commands, source hashes and bounded browser cases. CI remains the source of truth for native execution and merge readiness; local source generation alone never counts as a native pass. The [independent finish review](component-editing-finish-review.md) records inspected raster/source coverage separately.

The new controls follow the existing Impeccable Operate direction: Geist, achromatic glass planes, green actions and shared controls. The detector reported zero anti-patterns on the seven new UI files. Its one radius advisory is intentional: the 10px resize handle uses a 2px optical corner, rather than a panel/control radius that would turn it into a circle. Inspector controls retain standard rounded tokens. Native control CSS is prevented from changing editor handle geometry; inline editing pairs Studio text/background colors and keeps its draft mounted when navigation is locked.
